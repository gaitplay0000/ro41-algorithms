# Трассировка рекурсивной функции F(n) (факториал)

```csharp
static int F(int n)
{
    if (n <= 1) return 1;
    return n * F(n - 1);
}
```

## 1. Базовый случай и шаг рекурсии

- **Базовый случай:** `if (n <= 1) return 1;` — рекурсия прекращается, функция возвращает `1` без дальнейших вызовов. Условие `n <= 1` покрывает `n = 1`, `n = 0` (0! = 1) и любые отрицательные `n`.
- **Шаг рекурсии:** `return n * F(n - 1);` — задача сводится к такой же задаче с меньшим аргументом (`n - 1`), результат домножается на `n`.
- **Почему рекурсия завершается:** аргумент на каждом шаге строго уменьшается на 1 и за конечное число шагов достигает значения `<= 1`, то есть базового случая.

## 2. Ручная трассировка F(4)

### Спуск вниз по стеку (вызовы)

```
F(4)            n=4 > 1 → нужно посчитать 4 * F(3)
 └─ F(3)        n=3 > 1 → нужно посчитать 3 * F(2)
     └─ F(2)    n=2 > 1 → нужно посчитать 2 * F(1)
         └─ F(1) n=1 <= 1 → базовый случай, return 1
```

### Подъём вверх (возврат значений)

```
F(1) → 1
F(2) = 2 * F(1) = 2 * 1 = 2
F(3) = 3 * F(2) = 3 * 2 = 6
F(4) = 4 * F(3) = 4 * 6 = 24
```

### Таблица

| № | Вызов | Глубина | Что происходит | Возвращает |
|---|-------|---------|----------------|------------|
| 1 | F(4)  | 0 | n > 1, вызывает F(3), ждёт результат | 4 · 6 = **24** |
| 2 | F(3)  | 1 | n > 1, вызывает F(2), ждёт результат | 3 · 2 = **6** |
| 3 | F(2)  | 2 | n > 1, вызывает F(1), ждёт результат | 2 · 1 = **2** |
| 4 | F(1)  | 3 | базовый случай (n <= 1), рекурсии нет | **1** |

Порядок вызовов (вниз): F(4) → F(3) → F(2) → F(1).
Порядок возврата (вверх): F(1) → F(2) → F(3) → F(4).
Максимальная глубина стека: 4 кадра (глубины 0…3). Всего вызовов: 4.

### Проверка трассировки программой (C#)

```csharp
using System;

class Program
{
    static int F(int n, int depth = 0)
    {
        Console.WriteLine($"{new string(' ', depth * 2)}вызов F({n}), глубина {depth}");
        if (n <= 1)
        {
            Console.WriteLine($"{new string(' ', depth * 2)}F({n}) возвращает 1");
            return 1;
        }
        int result = n * F(n - 1, depth + 1);
        Console.WriteLine($"{new string(' ', depth * 2)}F({n}) возвращает {result}");
        return result;
    }

    static void Main() => F(4);
}
```

Вывод:

```
вызов F(4), глубина 0
  вызов F(3), глубина 1
    вызов F(2), глубина 2
      вызов F(1), глубина 3
      F(1) возвращает 1
    F(2) возвращает 2
  F(3) возвращает 6
F(4) возвращает 24
```

## 3. Что будет при F(-1), если заменить условие на `n == 1`

Код после замены:

```csharp
static int F(int n) { if (n == 1) return 1; return n * F(n - 1); }
```

**Трассировка F(-1):**

```
F(-1): -1 != 1 → F(-2)
F(-2): -2 != 1 → F(-3)
F(-3): -3 != 1 → F(-4)
...
```

**Почему так происходит.** Аргумент уменьшается на 1 при каждом вызове, то есть движется от `-1` в сторону `-∞`, а значение `1` лежит в противоположной стороне. Единственное условие выхода `n == 1` никогда не выполняется, базовый случай недостижим. Рекурсия не сходится к базовому случаю — это бесконечная рекурсия.

**К какой ошибке это приведёт.** Каждый вызов создаёт новый кадр на стеке вызовов (хранит параметр `n`, адрес возврата и т. д.), а возвращаться ни один вызов не может, так как все ждут результата следующего. Стек конечного размера (около 1 МБ на основном потоке в Windows) переполняется, и в .NET возникает **`StackOverflowException`** (переполнение стека). Это исключение нельзя перехватить через `try/catch`: среда выполнения аварийно завершает процесс.

Дополнительные замечания:

- Вызов `F(n - 1)` не находится в хвостовой позиции (после него ещё выполняется умножение на `n`), поэтому оптимизации хвостовой рекурсии нет, и кадры накапливаются.
- Та же проблема возникнет и для `F(0)` при условии `n == 1`: 0 → -1 → -2 → … Исходное условие `n <= 1` защищает от этого, так как покрывает все `n`, не превышающие 1.
- Отдельно от стека: для `n > 12` результат не помещается в `int` (13! > 2³¹ − 1), будет переполнение разрядной сетки (по умолчанию в `unchecked`-контексте — тихое, неверное значение). К вопросу о бесконечной рекурсии это не относится, но это ограничение функции.
