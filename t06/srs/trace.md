# Трассировка алгоритмов на массиве

Исходный массив: `a = {4, 1, 7, 3, 9}`, `n = 5`.

## 1. Циклический сдвиг влево на одну позицию

```csharp
int tmp = a[0];                    // буфер
for (int i = 0; i < n - 1; i++)
    a[i] = a[i + 1];
a[n - 1] = tmp;
```

| Шаг | i | Действие | Состояние массива после шага |
|-----|---|----------|------------------------------|
| 0 | — | `tmp = a[0]` (tmp = 4) | {4, 1, 7, 3, 9} |
| 1 | 0 | `a[0] = a[1]` | {1, 1, 7, 3, 9} |
| 2 | 1 | `a[1] = a[2]` | {1, 7, 7, 3, 9} |
| 3 | 2 | `a[2] = a[3]` | {1, 7, 3, 3, 9} |
| 4 | 3 | `a[3] = a[4]` | {1, 7, 3, 9, 9} |
| 5 | — | `a[n - 1] = tmp` (a[4] = 4) | **{1, 7, 3, 9, 4}** |

Буфер нужен, потому что `a[0]` перезаписывается на первом же шаге цикла. Без `tmp` значение 4 было бы потеряно. Цикл идёт до `i < n - 1`, так как у последнего элемента нет правого соседа, его значение берётся из буфера.

## 2. Разворот массива на месте

```csharp
for (int i = 0; i < n / 2; i++)
{
    int t = a[i];
    a[i] = a[n - 1 - i];
    a[n - 1 - i] = t;
}
```

Здесь `n / 2 = 5 / 2 = 2` (целочисленное деление), значит `i = 0, 1`.

| Шаг | i | Пара (i, n-1-i) | Обмен | Состояние массива |
|-----|---|-----------------|-------|-------------------|
| 0 | — | — | — | {4, 1, 7, 3, 9} |
| 1 | 0 | (0, 4) | a[0] ↔ a[4] | {9, 1, 7, 3, 4} |
| 2 | 1 | (1, 3) | a[1] ↔ a[3] | **{9, 3, 7, 1, 4}** |

Элемент `a[2] = 7` стоит в центре и остаётся на месте.

**Количество обменов: 2** (в общем случае `n / 2` с округлением вниз).

**Почему цикл идёт только до n / 2.** Каждый обмен ставит на место сразу два элемента: `a[i]` и `a[n - 1 - i]`. Пары `(i, n - 1 - i)` и `(n - 1 - i, i)` — это одна и та же пара. Когда `i` проходит середину, пары начинают повторяться. Повторный обмен возвращает элементы обратно, и разворот отменяется. Если бы цикл шёл до `n`, то:

- i = 2: пара (2, 2), элемент меняется сам с собой (холостой обмен);
- i = 3: пара (3, 1), обмен возвращает {9, 1, 7, 3, 4};
- i = 4: пара (4, 0), обмен возвращает {4, 1, 7, 3, 9}.

В итоге массив остался бы **неизменным**. При нечётном `n` средний элемент в пару не входит, ему обмен не нужен.

## 3. Поиск минимума: ошибка при `min = 0`

Ошибочный вариант (в `min` хранится значение):

```csharp
int min = 0;
for (int i = 0; i < n; i++)
    if (a[i] < min) min = a[i];
```

**Контрпример:** `a = {4, 1, 7, 3, 9}` (все элементы положительные).

| i | a[i] | a[i] < min? | min |
|---|------|-------------|-----|
| — | — | — | 0 |
| 0 | 4 | 4 < 0 — нет | 0 |
| 1 | 1 | 1 < 0 — нет | 0 |
| 2 | 7 | 7 < 0 — нет | 0 |
| 3 | 3 | 3 < 0 — нет | 0 |
| 4 | 9 | 9 < 0 — нет | 0 |

Результат 0, хотя в массиве нет нуля. Правильный ответ: 1. Алгоритм ошибается на любом массиве без отрицательных элементов и нуля, потому что начальное значение 0 «слишком мало» и ни с одним элементом не проигрывает сравнение. Начальное значение минимума должно быть не меньше любого элемента массива.

**Исправление:**

```csharp
int min = a[0];                    // первый элемент как кандидат
for (int i = 1; i < n; i++)
    if (a[i] < min) min = a[i];
```

Допустимо и `int min = int.MaxValue;` (тогда цикл с `i = 0`). Вариант с `a[0]` лучше тем, что результат всегда является элементом массива. Для пустого массива (`n == 0`) `a[0]` недоступен, поэтому до цикла нужна проверка `n > 0`.

Трассировка исправленного алгоритма на `{4, 1, 7, 3, 9}`:

| i | a[i] | a[i] < min? | min |
|---|------|-------------|-----|
| — | — | — | 4 |
| 1 | 1 | да | 1 |
| 2 | 7 | нет | 1 |
| 3 | 3 | нет | 1 |
| 4 | 9 | нет | 1 |

Результат: **1**.

**Замечание:** если в алгоритме `min = 0` означает *индекс* минимального элемента (`minIdx = 0`, сравнение `a[i] < a[minIdx]`), то это начальное значение корректно для непустого массива, и ошибки нет. Ошибка возникает именно тогда, когда в `min` хранится значение.
