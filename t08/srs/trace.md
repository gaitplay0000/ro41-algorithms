# T08 СРС — ручная трассировка строк

## 1. Trim() и Split(';')

Исходная строка: `s = "  Ахметов Ерлан;85 "` (длина 19: 2 пробела + `Ахметов Ерлан` (13) + `;` + `85` + 1 пробел).

**Шаг 1. `s.Trim()`** убирает пробелы по краям (2 в начале, 1 в конце):
`"Ахметов Ерлан;85"`, длина 16. Пробел внутри (между фамилией и именем) остаётся.

**Шаг 2. `.Split(';')`** делит по символу `;`, получается массив из 2 элементов:

| Индекс | Содержимое | Длина |
|---|---|---|
| 0 | `"Ахметов Ерлан"` | 13 |
| 1 | `"85"` | 2 |

Длина массива: 2. Разделитель `;` в элементы не попадает.

## 2. TryParse для `line = "Иванов Пётр;70;85;x"`

`line.Split(';')` → `["Иванов Пётр", "70", "85", "x"]` (4 элемента).

Предположение о реализации: `TryParseScores(line, out int[] scores)` считает частью 0 имя (не парсит), а части 1..N парсит через `int.TryParse`; при первой неудаче возвращает `false`.

| Индекс | Часть | Результат TryParse | Значение out |
|---|---|---|---|
| 0 | `"Иванов Пётр"` | не парсится (это имя; если вызвать — `false`) | 0 |
| 1 | `"70"` | `true` | 70 |
| 2 | `"85"` | `true` | 85 |
| 3 | `"x"` | `false` | 0 |

**TryParseScores вернёт `false`**, потому что часть `"x"` не является целым числом: `int.TryParse("x", out v)` возвращает `false` и записывает в `v` значение 0. Одна неверная оценка делает всю строку некорректной. Значения 70 и 85 успели разобраться, но результат метода — `false` (массив оценок считается недействительным и использоваться не должен).

## 3. `s += i` и StringBuilder

### Конкатенация

`s = ""` (литерал, создан до цикла и в подсчёт цикла не входит). Строки неизменяемы, поэтому каждое `s += i` создаёт новую строку.

| Шаг (i) | s до | Операция | s после | Новых string |
|---|---|---|---|---|
| 0 | `""` | `s + "0"` | `"0"` | 1 |
| 1 | `"0"` | `s + "1"` | `"01"` | 1 |
| 2 | `"01"` | `s + "2"` | `"012"` | 1 |
| 3 | `"012"` | `s + "3"` | `"0123"` | 1 |
| **Итого** | | | | **4** |

Итого 4 новые строки (5 вместе с исходной `""`); старые становятся мусором для GC. Примечание: `i.ToString()` для `int` тоже может создавать временную строку (в современных .NET для малых чисел берутся из кэша), а `Concat("", "0")` возвращает вторую строку без копирования, поэтому на практике число аллокаций может быть чуть меньше. Для учебной трассировки ответ: 4 объекта string.

### StringBuilder

`var sb = new StringBuilder();` создаётся 1 объект StringBuilder с внутренним буфером символов (по умолчанию ёмкость 16).

| Шаг (i) | Операция | Содержимое буфера | Новых string |
|---|---|---|---|
| 0 | `sb.Append(0)` | `0` | 0 |
| 1 | `sb.Append(1)` | `01` | 0 |
| 2 | `sb.Append(2)` | `012` | 0 |
| 3 | `sb.Append(3)` | `0123` | 0 |
| **Итого** | | | **0** |

`Append` дописывает символы в тот же буфер (4 символа < 16, расширение не нужно). Строка создаётся один раз, при `sb.ToString()`.

## 4. Почему `s.ToUpper()` не меняет `s`

Строки в C# неизменяемы (immutable): после создания содержимое объекта `string` изменить нельзя. Метод `ToUpper()` не изменяет объект, а возвращает **новую** строку. Если результат не присвоен, ссылка `s` по-прежнему указывает на старый объект, а новая строка теряется.

```csharp
string s = "Ахметов";
s.ToUpper();        // вернул "АХМЕТОВ", но результат отброшен; s == "Ахметов"
s = s.ToUpper();    // теперь s указывает на новую строку "АХМЕТОВ"
```
