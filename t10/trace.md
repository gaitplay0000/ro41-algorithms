# T10 СРС — трассировка сортировок и бинарного поиска

Сортировка по возрастанию. Индексы с 0.

## 1. Сортировка выбором, a = {5, 2, 9, 1, 7}

На проходе i ищется минимум среди a[i..n-1] (сравнений на проходе n-1-i), затем он меняется местами с a[i].

| Проход i | Индекс минимума | Массив после обмена | Сравнений на проходе |
|---|---|---|---|
| 0 | 3 (значение 1) | {1, 2, 9, 5, 7} | 4 |
| 1 | 1 (значение 2, уже на месте) | {1, 2, 9, 5, 7} | 3 |
| 2 | 3 (значение 5) | {1, 2, 5, 9, 7} | 2 |
| 3 | 4 (значение 7) | {1, 2, 5, 7, 9} | 1 |

**Общее число сравнений:** 4 + 3 + 2 + 1 = **10** (формула n(n-1)/2 при n = 5).
Число сравнений не зависит от исходного порядка элементов. Реальных обменов 3: на проходе 1 минимум уже стоит на своём месте.

## 2. Сортировка вставками, a = {4, 3, 2, 1}

На шаге i элемент key = a[i] вставляется в отсортированную часть a[0..i-1]: элементы больше key сдвигаются вправо на одну позицию.

| i | key | Число сдвигов | Массив после вставки |
|---|---|---|---|
| 1 | 3 | 1 (сдвинулась 4) | {3, 4, 2, 1} |
| 2 | 2 | 2 (сдвинулись 4, 3) | {2, 3, 4, 1} |
| 3 | 1 | 3 (сдвинулись 4, 3, 2) | {1, 2, 3, 4} |

**Всего сдвигов:** 1 + 2 + 3 = **6** (худший случай, n(n-1)/2).

**Уже отсортированный массив из 4 элементов** (например, {1, 2, 3, 4}): на каждом шаге i = 1, 2, 3 выполняется одно сравнение a[i-1] > key, оно ложно, сдвигов нет. Итого **3 сравнения** (n - 1), 0 сдвигов. Это лучший случай, сложность O(n).

## 3. Бинарный поиск в a = {1, 3, 5, 7, 9, 11, 13}

Индексы 0..6. Начальные границы lo = 0, hi = 6 (hi включительно), mid = lo + (hi - lo) / 2.
Решение: a[mid] == x → найден; a[mid] < x → lo = mid + 1; a[mid] > x → hi = mid - 1. Цикл идёт, пока lo <= hi.

### x = 7

| Шаг | lo | hi | mid | a[mid] | Решение |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 7 == 7, найден, вернуть индекс 3 |

Поиск закончился за 1 шаг, результат: **индекс 3**.

### x = 6

| Шаг | lo | hi | mid | a[mid] | Решение |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 7 > 6, hi = mid - 1 = 2 |
| 2 | 0 | 2 | 1 | 3 | 3 < 6, lo = mid + 1 = 2 |
| 3 | 2 | 2 | 2 | 5 | 5 < 6, lo = mid + 1 = 3 |
| 4 | 3 | 2 | — | — | lo > hi, цикл завершён |

Поиск закончился **неудачей**: элемента 6 в массиве нет. Классический вариант возвращает -1 (в стиле `Array.BinarySearch` — `~lo = -4`). Остановка с lo = 3 указывает позицию, куда можно вставить 6, не нарушив порядок.

**LowerBound(6)** возвращает первый индекс, для которого a[i] >= 6, то есть **3** (значение 7). Вариант на полуинтервале [lo, hi), lo = 0, hi = 7:

| Шаг | lo | hi | mid | a[mid] | Решение |
|---|---|---|---|---|---|
| 1 | 0 | 7 | 3 | 7 | 7 >= 6, hi = 3 |
| 2 | 0 | 3 | 1 | 3 | 3 < 6, lo = 2 |
| 3 | 2 | 3 | 2 | 5 | 5 < 6, lo = 3 |
| 4 | 3 | 3 | — | — | lo == hi, ответ 3 |

Для сравнения, LowerBound(7) тоже равен 3: 7 — первый элемент, не меньший 7.
